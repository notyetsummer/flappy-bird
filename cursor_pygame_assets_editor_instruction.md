# ТЗ для Cursor-Agent: интеграция бесплатных пиксельных ассетов и редактора уровней в Pygame-платформер

## 0. Режим работы агента

Ты работаешь с существующим Pygame-проектом платформера. Сейчас визуализация игры сделана через примитивы Pygame: `pygame.draw.rect`, `pygame.draw.circle`, `pygame.draw.line` и похожие конструкции.

Цель: минимально вовлекать разработчика. Разработчик должен в основном запускать проект, проверять результат и принимать изменения. Все рутинные действия — анализ структуры проекта, подбор бесплатных ассетов, загрузка, раскладка файлов, подключение спрайтов, создание редактора, сохранение форматов уровней и fallback-механизмы — должен выполнить агент.

Главный принцип: не ломать рабочую физику игры.

Ассеты должны заменить только визуальный слой. Логика движения, гравитации, столкновений и хитбоксов должна остаться на `pygame.Rect` или на уже существующей collision-системе проекта.

---

## 1. Что нужно сделать в целом

Нужно выполнить пять крупных задач:

1. Проанализировать текущую структуру проекта.
2. Найти, скачать и разложить бесплатные ассеты для 2D pixel-art платформера.
3. Интегрировать ассеты в игру вместо визуальных примитивов.
4. Создать редактор для выбора ассетов, редактирования уровней и тестирования игровых сцен.
5. Добавить режим безопасного fallback, чтобы игра продолжала запускаться даже при отсутствии части ассетов.

## 2. Ограничения и важные правила

### 2.1. Не переписывать игру заново

Не нужно превращать проект в новый движок. Вноси минимальные изменения в существующую архитектуру.

Если в проекте уже есть классы `Player`, `Enemy`, `Platform`, `Level`, `Camera`, `Game`, `World` или похожие сущности — используй их.

Если архитектура хаотичная, не делай полную переработку. Создай небольшой слой адаптации:

- `src/assets/asset_loader.py`
- `src/assets/asset_registry.py`
- `src/editor/level_editor.py`
- `src/levels/level_io.py`

### 2.2. Не заменять физику ассетами

`rect`, `hitbox`, `collision_rect` или аналогичные поля должны остаться основой физики.

Картинка должна рисоваться поверх:

```python
screen.blit(image, draw_position)
```

Если размер картинки не совпадает с хитбоксом, добавь визуальное смещение:

```python
draw_offset_x
draw_offset_y
```

### 2.3. Не использовать ассеты с сомнительной лицензией

По умолчанию использовать только:

- CC0
- Public Domain
- MIT для кода или инструментов, если понадобится
- явно бесплатные ассеты, где разрешено использование в играх

Не использовать автоматически:

- ассеты без лицензии
- ассеты с пометкой “personal use only”
- ассеты с запретом коммерческого использования
- ассеты, требующие покупки
- ассеты, для которых нужно вручную принимать нестандартное соглашение

Если лицензия неясна — пропустить ассет и записать причину в `assets/licenses/asset_sources.md`.

## 3. Автоматический поиск и загрузка бесплатных ассетов

### 3.1. Приоритетные источники

Сначала искать ассеты здесь:

1. Kenney
   - основной приоритет
   - искать платформерные pixel-art ассеты
   - приоритет CC0
   - пример: Kenney Pixel Platformer
   - https://kenney.nl/assets/pixel-platformer

2. OpenGameArt
   - использовать только ассеты с понятной лицензией
   - приоритет CC0
   - если лицензия CC-BY, записать автора и ссылку в файл лицензий
   - https://opengameart.org

3. itch.io
   - искать free pixel art platformer assets
   - перед загрузкой обязательно проверить лицензию конкретного набора
   - если лицензия неочевидна — не использовать
   - https://itch.io/game-assets/free/genre-platformer/tag-pixel-art

### 3.2. Что агент должен найти

Нужно найти и скачать минимальный рабочий набор:

- фон уровня
- тайлы земли/платформ
- декоративные тайлы
- персонаж игрока
- минимум один тип врага
- минимум один предмет, например монета, кристалл или ключ
- минимум одно препятствие, например шипы или яма
- простой UI/HUD, если найдётся подходящий набор

### 3.3. Как раскладывать ассеты

Создай структуру:

```text
assets/
  raw_downloads/
  backgrounds/
  player/
  enemies/
  tiles/
  obstacles/
  items/
  ui/
  licenses/
    asset_sources.md
    licenses.json
```

В `raw_downloads/` сохраняй исходные архивы или распакованные оригинальные наборы.

В рабочие папки копируй только реально используемые файлы.

### 3.4. Обязательный файл с лицензиями

Создай `assets/licenses/asset_sources.md`.

Формат:

```md
# Источники ассетов

## Asset pack name

- Source: URL
- Author: Author name / Unknown
- License: CC0 / Public Domain / CC-BY / Other
- Usage status: integrated / downloaded only / skipped
- Notes: краткое пояснение
```

Также создай машинно-читаемый файл `assets/licenses/licenses.json`:

```json
[
  {
    "name": "Kenney Pixel Platformer",
    "source_url": "https://kenney.nl/assets/pixel-platformer",
    "author": "Kenney",
    "license": "CC0",
    "status": "integrated",
    "notes": "Used for tiles, background and basic items"
  }
]
```

## 4. Интеграция ассетов в игру

### 4.1. Создать загрузчик ассетов

Создай файл:

```text
src/assets/asset_loader.py
```

Функциональность:

- загрузка PNG через `pygame.image.load(...).convert_alpha()`
- масштабирование в целое число раз
- кэширование загруженных изображений
- fallback при отсутствии файла
- предупреждение в консоль при missing asset

Пример интерфейса:

```python
image = asset_loader.load_image("player/idle_0.png", scale=3)
```

Требования:

```python
load_image(relative_path: str, scale: int = 1) -> pygame.Surface
load_frames(folder: str, scale: int = 1, sort: bool = True) -> list[pygame.Surface]
get_missing_asset_surface(width: int, height: int) -> pygame.Surface
```

### 4.2. Создать реестр ассетов

Создай файл:

```text
src/assets/asset_registry.py
```

Он должен хранить соответствия между игровыми сущностями и ассетами.

Пример:

```python
ASSETS = {
    "player": {
        "idle": ["player/idle_0.png", "player/idle_1.png"],
        "run": ["player/run_0.png", "player/run_1.png"],
        "jump": ["player/jump.png"]
    },
    "tiles": {
        "ground": "tiles/ground.png",
        "grass": "tiles/grass.png",
        "stone": "tiles/stone.png"
    },
    "enemies": {
        "slime": {
            "idle": ["enemies/slime_idle_0.png", "enemies/slime_idle_1.png"]
        }
    },
    "items": {
        "coin": ["items/coin_0.png", "items/coin_1.png"]
    },
    "obstacles": {
        "spikes": "obstacles/spikes.png"
    },
    "backgrounds": {
        "default": "backgrounds/default.png"
    }
}
```

### 4.3. Заменить визуальные примитивы на спрайты

Найди все места, где игровые сущности рисуются через:

```python
pygame.draw.rect
pygame.draw.circle
pygame.draw.line
pygame.draw.polygon
```

Замени их на `screen.blit(...)`, но только для игровых сущностей:

- игрок
- платформы
- враги
- предметы
- препятствия
- фоны
- декоративные объекты

Debug-отрисовку хитбоксов оставь, но сделай её выключенной по умолчанию.

Добавь настройку:

```python
DEBUG_DRAW_HITBOXES = False
```

Если включено:

```python
pygame.draw.rect(screen, (255, 0, 0), entity.rect, 1)
```

### 4.4. Игрок

Для игрока нужно добавить:

- `image`
- `animations`
- `state`
- `frame_index`
- `animation_timer`
- `facing_right`
- `draw_offset_x`
- `draw_offset_y`

Не менять существующее управление, если оно работает.

Логика состояния:

```text
если персонаж не на земле → jump/fall
если движется по X → run
иначе → idle
```

Если нет готовой анимации — использовать один статичный кадр.

### 4.5. Враги

Для врагов добавить:

- выбор типа врага через строковый id, например `slime`, `bat`, `crawler`
- `image` или `animations`
- `rect` как физический хитбокс
- возможность размещения через редактор

Не добавлять сложный искусственный интеллект, если его ещё нет.

Если враги уже существуют — только заменить визуал.

### 4.6. Платформы и тайлы

Для платформ:

- оставить collision rect
- добавить `tile_id`
- добавить `image`
- рисовать через `blit`

Пример:

```python
Platform(x, y, width, height, tile_id="ground")
```

Если платформа больше одного тайла, отрисовывать её как повторение тайла по сетке.

### 4.7. Предметы и препятствия

Добавить поддержку:

- `items`
- `obstacles`
- `decorations`

Каждый объект должен иметь:

```python
id
type
rect
asset_id
properties
```

Пример:

```json
{
  "id": "coin_001",
  "type": "item",
  "asset_id": "coin",
  "x": 420,
  "y": 320,
  "properties": {
    "value": 1
  }
}
```

## 5. Отдельный пункт: редактор игры и уровней

Создай встроенный редактор уровней для проекта. Это должен быть отдельный режим запуска, а не внешняя сложная программа.

Желаемый запуск:

```bash
python main.py --editor
```

Или отдельный файл:

```bash
python editor.py
```

Выбери вариант, который проще интегрировать в текущий проект.

### 5.1. Основные задачи редактора

Редактор должен позволять без правки кода:

- выбирать фон уровня
- выбирать модель/спрайт персонажа
- выбирать модели/спрайты врагов
- выбирать тайлы платформ
- редактировать карту уровня
- расставлять платформы
- расставлять препятствия
- расставлять противников
- расставлять предметы
- устанавливать точку старта уровня
- устанавливать точку конца уровня
- менять размер уровня
- увеличивать ширину уровня
- увеличивать высоту уровня
- делать уровни нестандартной формы
- сохранять уровень в JSON
- загружать уровень из JSON
- запускать тест уровня прямо из редактора

### 5.2. Минимальный UI редактора

Сделай простой интерфейс на Pygame, без внешних GUI-фреймворков.

Экран редактора разделить на зоны:

```text
┌────────────────────────────────────────────┐
│ Верхняя панель: Save | Load | Test | Mode  │
├───────────────┬────────────────────────────┤
│ Палитра       │                            │
│ ассетов       │      Рабочая область        │
│               │      карты уровня           │
│ tiles         │                            │
│ enemies       │                            │
│ items         │                            │
│ obstacles     │                            │
│ backgrounds   │                            │
└───────────────┴────────────────────────────┘
```

Если полноценный UI занимает слишком много времени, сделать минимальный редактор с клавиатурными режимами и мышью.

### 5.3. Режимы редактора

Добавить режимы:

```text
1 — Paint tiles
2 — Place platforms
3 — Place enemies
4 — Place items
5 — Place obstacles
6 — Set player start
7 — Set level end
8 — Select/delete objects
9 — Background selection
0 — Test level
```

### 5.4. Управление редактором

Минимальное управление:

```text
ЛКМ — поставить выбранный объект
ПКМ — удалить объект под курсором
Колёсико мыши — сменить выбранный ассет в текущей категории
WASD / стрелки — двигать камеру редактора
Ctrl+S — сохранить уровень
Ctrl+O — загрузить уровень
T — запустить тест уровня
Esc — выйти из теста обратно в редактор
+ / - — изменить масштаб редактора
[ / ] — изменить размер кисти
G — включить/выключить сетку
H — включить/выключить хитбоксы
```

### 5.5. Выбор и тестирование ассетов

Редактор должен иметь Asset Preview Panel.

Функции:

- показать выбранный ассет
- показать его размер
- показать путь к файлу
- если это анимация — проигрывать анимацию
- позволить выбрать ассет для сущности
- позволить протестировать ассет в уровне

Для персонажа:

- выбрать набор спрайтов игрока
- проверить idle/run/jump/fall
- проверить направление влево/вправо

Для врагов:

- выбрать тип врага
- выбрать idle/move animation
- поставить врага на карту
- запустить тест уровня

Для фона:

- выбрать background id
- включить/выключить parallax, если уже есть камера
- если parallax не реализован, просто растягивать или повторять фон

### 5.6. Редактирование карты

Поддержать два типа объектов:

1. Tile grid
2. Free objects

Tile grid нужен для земли, платформ, стен, декоративных тайлов.

Free objects нужны для:

- игрока
- врагов
- предметов
- препятствий
- точки конца уровня
- декоративных объектов нестандартного размера

### 5.7. Размер и форма уровня

Уровень не должен быть ограничен размером экрана.

Добавить параметры:

```json
"width_tiles": 120,
"height_tiles": 40,
"tile_size": 48
```

Редактор должен позволять:

- увеличить ширину уровня
- уменьшить ширину уровня с предупреждением о потере объектов за границей
- увеличить высоту уровня
- уменьшить высоту уровня с предупреждением
- создавать пустые области
- создавать вертикальные уровни
- создавать широкие уровни
- создавать уровни с несколькими маршрутами
- создавать уровни причудливой формы через пустые клетки

Важно: “причудливая форма” не означает сложную геометрию collision polygon. Для первого этапа достаточно сетки, где часть клеток пустые, часть заняты тайлами.

### 5.9. Загрузка уровня в игре

Игра должна уметь запускать уровень из JSON:

```bash
python main.py --level levels/level_001.json
```

Если аргументы командной строки в проекте ещё не используются, добавить через `argparse`.

Требования:

- если уровень не указан, загружать default level
- если файл уровня повреждён, вывести понятную ошибку
- если в уровне указан отсутствующий ассет, использовать fallback-картинку

### 5.10. Тестовый режим из редактора

В редакторе должна быть кнопка или клавиша `T` для запуска текущего уровня.

Алгоритм:

1. Сохранить текущий уровень во временный файл:

```text
levels/_editor_test_level.json
```

2. Запустить игру в режиме теста.
3. При нажатии `Esc` вернуться в редактор.

Если проще технически — не запускать отдельный процесс, а переключать состояние приложения:

```text
EDITOR_MODE → PLAYTEST_MODE → EDITOR_MODE
```

Выбери более простой вариант для текущей архитектуры.

## 7. Fallback-режим

Игра не должна падать, если:

- не найден asset-файл
- отсутствует папка ассетов
- повреждён один PNG
- в JSON уровня указан неизвестный asset_id
- отсутствует анимация врага или игрока

В этих случаях:

1. Вывести warning в консоль.
2. Использовать fallback surface.
3. Продолжить запуск.

Fallback surface сделать визуально заметным:

- фиолетово-чёрная шахматка
- или яркий прямоугольник с подписью `MISSING`

## 9. Проверка после выполнения

После внесения изменений проверь:

1. Игра запускается без ошибок.
2. Игрок отображается спрайтом.
3. Платформы отображаются тайлами.
4. Фон отображается.
5. Хотя бы один враг отображается спрайтом.
6. Хотя бы один предмет отображается спрайтом.
7. Старые коллизии работают.
8. Игрок не проваливается сквозь платформы.
9. Редактор запускается.
10. В редакторе можно поставить платформу.
11. В редакторе можно поставить врага.
12. В редакторе можно поставить предмет.
13. В редакторе можно задать старт уровня.
14. В редакторе можно задать конец уровня.
15. Уровень сохраняется в JSON.
16. Уровень загружается из JSON.
17. Тест уровня запускается из редактора.
18. При отсутствующем ассете игра не падает.

## 10. Предпочтительный порядок выполнения

Делай работу по этапам и после каждого этапа запускай проект.

### Этап 1. Анализ проекта

- Найди главный файл запуска.
- Найди игровой цикл.
- Найди отрисовку.
- Найди классы игрока, платформ, врагов, предметов.
- Найди текущий формат уровня, если он есть.

### Этап 2. Инфраструктура ассетов

- Создай папки.
- Создай загрузчик.
- Создай реестр.
- Создай fallback.

### Этап 3. Интеграция минимального визуала

- Подключи фон.
- Подключи игрока.
- Подключи платформы.
- Подключи один предмет.
- Подключи одного врага, если враги уже есть.

### Этап 4. JSON-уровни

- Добавь сохранение уровня.
- Добавь загрузку уровня.
- Добавь запуск уровня через аргумент командной строки.

### Этап 5. Редактор

- Создай режим редактора.
- Добавь камеру редактора.
- Добавь сетку.
- Добавь палитру ассетов.
- Добавь размещение объектов.
- Добавь сохранение/загрузку.
- Добавь playtest.

### Этап 6. Документация и проверка

- Обнови README.
- Проверь запуск.
- Проверь fallback.
- Проверь лицензии.

## 11. Что нельзя делать

Не делай следующее:

- не переписывай игру с нуля
- не удаляй старую механику без необходимости
- не меняй управление игроком без необходимости
- не ломай collision logic
- не подключай тяжёлые GUI-фреймворки без необходимости
- не используй ассеты с непонятной лицензией
- не интегрируй ассеты, требующие оплаты
- не скачивай ассеты из сомнительных источников
- не делай редактор зависимым от конкретного экрана или разрешения

## 13. Минимальный ожидаемый результат

Работа считается выполненной на минимально приемлемом уровне, если:

1. Игра запускается.
2. Старые прямоугольники заменены хотя бы на базовые спрайты игрока, платформ, предметов и фона.
3. Физика и коллизии не сломаны.
4. Есть папка `assets/` с понятной структурой.
5. Есть файл лицензий ассетов.
6. Есть редактор уровня.
7. В редакторе можно создать простой уровень, сохранить его, загрузить и протестировать.
8. Отсутствие ассета не приводит к падению игры.

## 14. Главная логика проекта

Текущая игра на прямоугольниках — это не мусорный прототип, а хорошая основа. Прямоугольники должны остаться как невидимая физическая модель. Ассеты должны стать визуальной оболочкой поверх этой модели.

Редактор нужен не как отдельный идеальный инструмент, а как способ быстро собирать уровни без ручной правки кода. Поэтому сначала сделать простой, но работающий редактор, а не красивый интерфейс.
